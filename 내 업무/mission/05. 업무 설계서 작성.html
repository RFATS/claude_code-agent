05. 업무 설계서 작성

학습 목표
반복 업무 후보를 발굴하고, Agent에게 맡기기 적합한 업무를 선정할 수 있습니다.
업무에 필요한 입력 자료와 결과물의 기준을 정리할 수 있습니다.
하나의 업무를 세부 Task로 나누고, 코드 / AI / 사람의 역할을 구분할 수 있습니다.
이후 Multi-Agent 팀 설계에 활용할 업무 설계서를 완성할 수 있습니다.

2. 자동화할 업무를 고르는 눈

2-1. 자동화 후보를 찾는 세 가지 기준
처음부터 AI가 할 수 있는 업무만 찾으려고 하면 후보가 지나치게 좁아질 수 있습니다.
먼저 내가 반복해서 하는 일 중 “누가 좀 대신 해줬으면 좋겠다”고 느끼는 업무를 꺼냅니다.
지금은 AI가 할 수 있는지 판단하지 않습니다. 후보를 충분히 꺼낸 뒤 다음 STEP에서 하나씩 살펴봅니다.
Pain Point는 일하면서 반복해서 걸리는 답답한 지점이에요. 아래 세 가지 신호로 찾습니다.

4. 결과물 샘플 생성하기

4-1. 원하는 결과물 샘플 생성하기
입력 자료를 정했다면, 이제 업무가 끝났을 때 어떤 결과물이 나와야 하는지 정합니다.
결과물이 어떤 모습이어야 하는지와 어떤 내용이 들어가야 하는지 작성합니다.
예시는 Claude의 출력 형식, 어조, 구조를 조정하는 가장 신뢰할 수 있는 방법 중 하나입니다.
잘 만들어진 몇 가지 예시("few-shot" 또는 "multishot")는 정확성과 일관성을 향상시킵니다.
먼저 실제 결과물을 만들기 전에 결과물의 형태와 구성을 정합니다.
작성한 내용을 바탕으로 빠진 부분이 있는지 Claude와 함께 확인합니다.
파일은 
reference/example.html
로 저장합니다. Agent가 따라 만들 기준 샘플이 이 파일입니다.
결과물 샘플은 HTML로 만듭니다.
실제 업무의 최종 결과물은 보고서, 엑셀, 대시보드 등 다양할 수 있습니다.
이번 실습에서는 결과물의 구조와 완성된 모습을 바로 열어 확인할 수 있도록 HTML로 샘플을 만듭니다.
중요한 것은 HTML 자체가 아니라, 이후 Agent가 “이런 구성과 수준으로 만들어야 한다”라고 참고할 기준을 만드는 것입니다.
@guide/업무설계_가이드.md를 참고해서 STEP 3을 진행해줘. 내가 원하는 최종 결과물은 아래와 같아. ------------[아래 내용 작성 후 클로드와 대화하세요]------------ - 결과물 형태: [예: 주요 현황을 한눈에 보는 대시보드 / 분석 내용을 순서대로 정리한 보고서] - 구성: - [들어갈 내용 1] - [들어갈 내용 2] - [들어갈 내용 3]

5. 업무를 세부 단계로 쪼개기

5-1. 세부 Task와 실행 주체 정하기
하나의 큰 업무처럼 보여도 실제로는 여러 Task가 연결되어 있습니다.
앞에서 정한 입력 자료를 가지고 결과물을 만들기까지, 내가 실제로 하는 업무 흐름을 먼저 적어봅니다.
Claude가 업무 흐름을 살펴보고 적절한 크기의 Task로 나누면서, 각 Task를 코드 / AI / 사람 중 누가 맡는 것이 적절한지도 함께 구분합니다.
모든 일을 AI에게 맡기는 것이 아니라, 규칙적인 처리는 코드, 분석·해석·작성은 AI, 승인·최종 판단은 사람에게 맡깁니다.

5-2. AI가 맡은 일에 무엇이 더 필요할까?
실행 주체를 정했다면, 각 Task에 추가 기능이 필요한지 생각해봅니다.
같은 방법이나 기준을 반복해서 적용한다면 Skill을 활용할 수 있습니다.
외부 데이터나 시스템의 기능을 사용해야 한다면 MCP를 활용할 수 있습니다.
많은 문서나 지식에서 필요한 내용을 찾아 참고해야 한다면 RAG를 활용할 수 있습니다.
이런 Task라면
활용할 수 있는 것

MCP

업무 선정 — 반복·시간소모·AI 가능성을 기준으로 Agent에게 맡길 업무를 정했습니다.
입력 자료 준비 — 업무에 필요한 입력 자료를 정리하고, 실습용 가상 데이터를 만들었습니다.
결과물 기준 만들기 — 원하는 결과물의 형태와 구성을 정하고, Agent가 참고할 HTML 샘플을 만들었습니다.
업무 분해 — 전체 업무를 세부 Task로 나누고, 각 Task를 코드 / AI / 사람 중 누가 맡을지 구분했습니다.
