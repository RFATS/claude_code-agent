# Gen / Eval 패턴 가이드

## Gen / Eval이란?

AI가 결과물을 생성하고,
다른 AI가 정해진 기준에 따라 결과물을 검토하는 패턴입니다.

검토 결과가 기준을 충족하면 다음 단계로 진행하고,
기준을 충족하지 못하면 수정한 뒤 다시 검토합니다.


## Gen / Eval의 기본 구조

Gen / Eval은 다음과 같은 흐름으로 동작합니다.

[AI: 결과 생성]
        ↓
[AI: 결과 검토]
        ↓
   ┌────┴────┐
   ↓         ↓
 PASS       FAIL
   ↓         ↓
다음 단계   수정
             ↓
          다시 검토


생성하는 역할과 검토하는 역할을 분리하여
결과물의 품질을 확인하고 개선할 필요가 있을 때 사용합니다.


## Gen / Eval을 적용하기 좋은 경우

업무설계서와 현재 Workflow에서
AI가 만든 결과물 중 별도의 검토가 필요한 부분을 찾습니다.


### 1. 중요한 결과물을 만드는 경우

AI가 만든 결과물이
이후 업무나 의사결정에 직접 사용되는 경우입니다.

예시
- 보고서 작성 → 보고서 검토
- 분석 결과 작성 → 분석 내용 검토
- 제안서 작성 → 제안 내용 검토


### 2. 명확한 검토 기준이 있는 경우

결과물이 정해진 업무 기준을 충족하는지
확인할 수 있는 경우입니다.

예시
- 필수 항목이 모두 포함되었는가?
- 지정된 형식을 따랐는가?
- 근거 없이 작성된 내용이 없는가?
- 업무설계서의 기준을 충족하는가?


### 3. 수정 후 다시 검토할 가치가 있는 경우

한 번의 생성으로 끝내기보다
검토 결과를 바탕으로 수정하면 품질을 높일 수 있는 경우입니다.

예시

[AI: 보고서 작성]
        ↓
[AI: 보고서 검토]
        ↓
      FAIL
        ↓
[AI: 보고서 수정]
        ↓
[AI: 다시 검토]


## Gen / Eval로 만들지 않는 경우

다음 중 하나에 해당하면 Gen / Eval로 추천하지 않습니다.

- 결과물을 별도로 검토할 필요가 없는 단순 AI Task
- 검토 기준을 명확하게 정하기 어려운 Task
- 검토 결과와 관계없이 사람이 반드시 직접 판단해야 하는 Task
- 반복 검토를 해도 실질적인 품질 개선 효과가 없는 Task

모든 AI Task에 Reviewer를 붙이지 않습니다.

검토가 실제로 필요한 결과물에만
Gen / Eval을 추천합니다.


## Gen / Eval 추천 기준

업무설계서와 `workflow.md`를 보고
AI가 생성하는 결과물 중 검토가 필요한 부분을 찾습니다.

다음 기준으로 검토합니다.

1. AI가 명확한 결과물을 생성하는가?
2. 그 결과물을 평가할 수 있는 기준이 있는가?
3. 기준 미달 시 수정할 수 있는가?
4. 수정 후 다시 검토하는 것이 의미가 있는가?

적합한 경우에만 Gen / Eval 구조를 추천합니다.

업무설계서에 없는 검토 기준을
임의로 확정하지 않습니다.


## 생성과 검토 역할 정하기

Gen / Eval을 추천할 때는
누가 결과물을 만들고 누가 검토할지 구분합니다.

예시

[Generator: 보고서 작성]
          ↓
[Evaluator: 보고서 검토]

Generator는 결과물을 만드는 역할을 담당하고,
Evaluator는 결과물을 직접 수정하지 않고
정해진 기준에 따라 검토합니다.

Evaluator가 수정까지 담당하게 하지 않습니다.

수정이 필요하다면
검토 결과를 Generator에게 전달하여 수정하도록 합니다.


## PASS / FAIL 기준 정하기

Evaluator는 결과물을 검토한 뒤
PASS 또는 FAIL을 판단합니다.

PASS / FAIL 기준은
업무설계서의 업무 기준이나 결과물 요구사항을 우선 사용합니다.

예시

검토 기준
- 필수 항목이 모두 포함되어 있는가?
- 지정된 형식을 따르고 있는가?
- 분석 결과에 근거가 제시되어 있는가?

모든 기준 충족 → PASS
하나 이상 미충족 → FAIL

업무설계서에 없는 기준이나 숫자를
임의로 만들지 않습니다.


## FAIL 시 돌아갈 위치 정하기

FAIL이 발생했을 때
어디로 돌아가 수정할지도 명확하게 정합니다.

기본적으로 Evaluator가 발견한 문제를
결과물을 만든 Generator에게 전달합니다.

예시

[AI: 보고서 작성]
        ↓
[AI: 보고서 검토]
        ↓
   ┌────┴────┐
   ↓         ↓
 PASS       FAIL
   ↓         ↓
완료      [보고서 수정]
             ↓
         다시 검토

Evaluator는 문제점과 수정이 필요한 부분을 전달하고,
Generator가 이를 반영하여 결과물을 다시 생성하거나 수정합니다.


## 반복 횟수 제한

Gen / Eval이 끝없이 반복되지 않도록
최대 반복 횟수를 정합니다.

업무설계서에 반복 횟수가 정해져 있다면
해당 기준을 사용합니다.

별도의 기준이 없다면
사용자에게 최대 반복 횟수를 확인합니다.

최대 반복 횟수에 도달했는데도
PASS하지 못한 경우에는
무한히 다시 실행하지 않습니다.

사람이 결과와 검토 내용을 확인할 수 있도록
Workflow를 종료하거나 사람에게 넘기는 구조를 사용합니다.

예시

[Generator]
     ↓
[Evaluator]
     ↓
   FAIL
     ↓
[Generator 수정]
     ↓
[Evaluator 재검토]
     ↓
최대 반복 횟수 도달
     ↓
[사람: 확인]


## Workflow 시각화 원칙

Gen / Eval을 검토할 때는
`workflow.md`에 저장된 현재 Workflow를 기준으로 합니다.

코드 / AI / 사람 Task를 모두 포함하여
Gen / Eval이 전체 Workflow의 어디에 들어가는지 보여줍니다.

기존 Workflow의 Task나 연결 관계를
임의로 삭제하거나 변경하지 않습니다.

이전 단계에서 확정된 Parallel과 Router 구조가 있다면
그 구조도 그대로 유지합니다.


## 결과 표현 방법

길게 분석하거나
모든 Task에 대한 검토표를 출력하지 않습니다.

Gen / Eval을 추천할 경우
다음 내용만 간단히 보여줍니다.

- 대상 AI Task
- Generator 역할
- Evaluator 역할
- 주요 검토 기준
- FAIL 시 돌아갈 Task
- 최대 반복 횟수
- Gen / Eval을 적용하는 이유


### 추천 구조 시각화

추천한 Gen / Eval을 적용했을 때의 전체 Workflow를
상자와 화살표로 시각화합니다.

기존 Parallel / Router 등 이미 확정된 구조는 유지하고,
추천하는 Gen / Eval 부분만 추가하여 보여줍니다.

예시

[AI: 데이터 분석]
        ↓
[AI: 보고서 작성] ←──────────┐
        ↓                    │
[AI: 보고서 검토]             │
        ↓                    │
   ┌────┴────┐               │
   ↓         ↓               │
 PASS       FAIL ─────────────┘
   ↓
[사람: 최종 확인]


## 사용자 확인

추천한 Gen / Eval 구조를 바로 확정하지 않습니다.

추천 결과와 전체 Workflow를 보여준 뒤
사용자에게 다음 내용을 확인합니다.

- Generator와 Evaluator 역할
- 검토 기준
- FAIL 시 돌아갈 위치
- 최대 반복 횟수

마지막에 다음과 같이 확인합니다.

"이 Gen / Eval 구조를 Workflow에 반영할까요?"

사용자가 수정을 요청하면
요청한 내용을 반영하여 구조를 다시 보여주고 확인받습니다.


## Workflow 확정 및 저장

사용자가 Gen / Eval 구조를 확정하면
확정된 내용만 현재 Workflow에 반영합니다.

기존 `workflow.md`에 저장된 내용과
이미 확정된 Parallel / Router 구조는 그대로 유지합니다.

Gen / Eval이 반영된 전체 Workflow를 다시 정리하고,
현재 폴더의 `workflow.md` 파일을 업데이트합니다.

`workflow.md`에는 최소한 다음 내용을 유지합니다.

- 전체 Task의 실행 순서
- 각 Task의 실행 주체: 코드 / AI / 사람
- 확정된 Parallel 구조
- 확정된 Router 구조
- 확정된 Gen / Eval 구조
- PASS / FAIL 조건
- FAIL 시 돌아갈 Task
- 최대 반복 횟수
- Task 간 연결 관계
- 전체 Workflow 시각화

사용자가 확정하기 전에는
`workflow.md`를 수정하지 않습니다.
