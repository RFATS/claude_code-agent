# 업무 설계 가이드

이 가이드는 사용자의 업무를 Agent로 설계하기 위한 진행 가이드입니다.

최종적으로 `업무설계서.md`를 완성합니다.


## 진행 규칙

- 사용자가 요청한 STEP만 진행합니다.
- 다음 STEP으로 임의로 넘어가지 않습니다.
- 사용자가 말하지 않은 업무 내용은 임의로 추가하지 않습니다.
- 확인이 필요한 내용이 있다면 사용자에게 질문합니다.
- 사용자가 확인한 내용만 `업무설계서.md`에 반영합니다.
- 기존 `업무설계서.md`의 내용은 별도 요청이 없다면 수정하지 않습니다.
- 모든 답변은 한국어를 기반으로 합니다.
- 사용자에게 선택이나 확인을 요청할 때는 가능한 경우 마우스로 클릭할 수 있는 UI를 사용합니다.


# STEP 1. 오늘 설계할 업무 정하기

사용자가 Agent에게 맡겨보고 싶은 업무 3개와
각 업무의 빈도, 1회 소요시간을 알려주면
아래 기준으로 우선순위를 비교합니다.


## 우선순위 계산

빈도 점수 × 소요시간 점수 × AI 가능성 점수로
총점을 계산합니다.

각 항목은 1~5점이며 최대 점수는 125점입니다.

| 점수 | 빈도 | 소요시간 (1회) | AI가 해낼 가능성 |
|---|---|---|---|
| 5 | 매일 | 2시간 이상 | 규칙이 문서로 있고, 입력 자료가 파일로 정리돼 있음 |
| 3 | 매주 | 30분~1시간 | 규칙이 머릿속에 있지만 말로 설명할 수 있음 |
| 1 | 분기에 한 번 이하 | 10분 이하 | 매번 상황이 달라 사람 판단이 대부분임 |

4점과 2점은 그 사이로 판단합니다.

AI가 해낼 가능성을 판단할 때는 아래 기준도 함께 참고합니다.


### AI에 맡기기 좋은 신호

- 규칙이 문서(매뉴얼·양식)로 있음
- 입력이 엑셀·양식처럼 정형화돼 있음
- 결과물 형태가 정해져 있음 (보고서·표·메일)
- 틀려도 검토 단계에서 잡을 수 있음


### 맡기기 전에 한 번 더 따져 볼 신호

- 고도의 창의성이나 전략 판단이 핵심임
- 인사·예산 배분처럼 조직의 판단이 필요함
- 실수 한 번이 치명적임
- 데이터가 없거나 매번 완전히 다름

결과는 반드시 채팅창에 아래 형식의 표로 보여줍니다.

| 순위 | 업무 | 빈도 점수 | 소요시간 점수 | AI 가능성 점수 | 총점 | 판단 근거 |
|---|---|---|---|---|---|---|

점수가 비슷하면 결과를 확인하기 쉬운 업무를 먼저 제시합니다.

특정 사람에게만 몰리는 병목 업무가 있다면
점수가 조금 낮더라도 우선 후보로 고려할 수 있다고 알려줍니다.

점수가 가장 높은 업무를 자동으로 선택하지 않습니다.
결과를 보여준 뒤 사용자에게 오늘 설계할 업무 하나를 선택하도록 요청합니다.

사용자가 업무를 선택하면 선택한 업무만
`업무설계서.md`에 아래 형식으로 저장합니다.

## 실습용 입력 자료 생성

`업무설계서.md`에 입력 자료를 저장한 뒤,
정리된 내용을 기준으로 실습에서 사용할 가상의 입력 자료를 생성합니다.

조건:

- 공개 정보 또는 가상의 내용만 사용합니다.
- 실제 회사명·담당자·사내 데이터는 사용하지 않습니다.
- `업무설계서.md`에 적힌 파일 형식이 있다면 해당 형식으로 만듭니다.
- 엑셀(.xlsx), 워드(.docx), 파워포인트(.pptx), 텍스트(.txt), 데이터(.csv), 문서(.pdf)처럼 파일로 만들 수 있는 자료만 생성합니다.
- 도면·사진처럼 글과 표만으로 재현하기 어려운 자료는 억지로 만들지 않습니다.
- 웹에서 직접 찾아야 하는 자료나 MCP로 조회할 자료는 생성하지 않습니다.
- 애매한 부분이 있을 때만 사용자에게 먼저 질문합니다.
- 완성한 파일은 모두 `data/` 폴더에 저장합니다.
- 기존 `업무설계서.md`는 수정하지 않습니다.

파일 생성이 끝나면 생성한 파일 목록을 사용자에게 알려주고
STEP 2를 종료합니다.

## 결과물 샘플 생성

`업무설계서.md`에 결과물을 저장한 뒤,
정리된 결과물 형태와 구성을 기준으로 결과물 샘플 1개를 생성합니다.

결과물 샘플은 반드시 HTML 파일로 만듭니다.

사용자가 워드, 엑셀, PDF, PPT 등 다른 형식의 결과물을 원하더라도
실습에서 사용하는 결과물 샘플은 해당 결과물의 구조와 내용을 보여주는
HTML 형태로 시각화합니다.

조건:

- 반드시 standalone HTML 파일 1개로 만듭니다.
- 파일은 `reference/example.html`로 저장합니다.
- `업무설계서.md`에서 정한 결과물 형태와 구성은 유지합니다.
- `data/` 폴더의 내용은 사용하지 않습니다.
- 별도의 가상 내용으로 작성합니다.
- 빈칸이나 안내 문구 없이 실제 완성본처럼 채웁니다.
- 실제 회사명, 실제 담당자, 실제 사내 데이터는 사용하지 않습니다.
- 결과물의 내용보다 구조와 완성 수준을 참고할 수 있게 만듭니다.
- 기존 `업무설계서.md`는 수정하지 않습니다.
- HTML 외의 형식으로 결과물 샘플을 만들지 않습니다.

생성이 끝나면
`reference/example.html`이 생성되었음을 사용자에게 알려주고
STEP 3을 종료합니다.


# STEP 4. 업무를 Task로 나누고 실행 주체 정하기

현재 폴더의 `업무설계서.md`를 읽습니다.

사용자가 작성한 업무 단계는
완성된 Task 목록이 아니라 전체 업무 흐름을 설명하기 위한 초안입니다.

사용자의 초안을 바탕으로
각 업무를 코드 / AI / 사람 중 누가 수행하는 것이 적절한지 판단하면서
전체 업무를 5~7개 정도의 주요 Task로 구체화합니다.

사용자가 입력한 단계 수를 그대로 유지할 필요는 없습니다.


## Task를 나누는 기준

Task는 세부 행동 하나하나가 아니라
하나의 목적을 가진 업무 단위로 나눕니다.

실행 주체가 같고 하나의 목적을 위해 연속적으로 수행되는 작업은
가능하면 하나의 Task로 묶습니다.

예:

`파일 취합 → 데이터 병합 → 형식 정리 → 필요한 값 계산`

위 작업들이 하나의 규칙적인 데이터 처리 과정이라면

`입력 데이터 취합 및 전처리 / 코드`

처럼 하나의 Task로 묶습니다.

반대로 하나의 업무 단계 안에
실행 주체가 다른 일이 함께 포함되어 있다면
각각 별도의 Task로 나눕니다.

예:

`납기 상태를 확인하고 지연 원인을 분석`

→ `납기 상태 확인 / 코드`  
→ `지연 원인 분석 / AI`

단순히 처리 순서나 방법이 다르다는 이유만으로
Task를 세분화하지 않습니다.

전체적으로 5~7개 정도의 주요 Task가 되도록 정리하되,
개수를 맞추기 위해 불필요하게 세분화하거나
사용자가 실제로 하지 않는 업무를 추가하지 않습니다.


## 실행 주체 구분

각 Task를 아래 기준으로 코드 / AI / 사람 중 하나로 구분합니다.

- 코드: 규칙과 처리 방식이 명확한 반복 작업
- AI: 자료를 읽고 분석·해석·비교·요약·작성처럼 판단이 필요한 작업
- 사람: 승인·확인·의사결정처럼 사람이 직접 판단해야 하는 작업

현재 사람이 직접 하고 있는 일이라도
AI에게 위임할 수 있는 분석·해석·비교·요약·작성 업무라면
AI Task로 구분할 수 있습니다.

모든 Task를 AI에게 맡기는 것이 목적은 아닙니다.


## AI Task 최소 조건

최종 Task에는 반드시 1개 이상의 AI Task가 포함되어야 합니다.

처음 구분했을 때 AI Task가 없다면
사용자가 작성한 업무 흐름을 다시 확인하여
아래와 같은 일이 기존 업무에 포함되어 있는지 찾아봅니다.

- 자료를 읽고 의미를 해석하는 일
- 여러 정보나 대상을 비교하는 일
- 주요 이슈나 특징을 찾는 일
- 원인이나 영향을 분석하는 일
- 핵심 내용을 요약하는 일
- 보고서·대시보드·메일 등의 내용을 작성하는 일

이러한 일이 기존 Task 안에 포함되어 있다면
규칙적으로 처리할 부분과 AI가 판단할 부분을 나눌 수 있습니다.

예:

`협력사별 납기 현황 분석`

→ `협력사별 납기 현황 집계 / 코드`  
→ `주요 지연 원인 및 특이사항 분석 / AI`

단, AI Task를 만들기 위해
사용자가 실제로 하지 않는 업무를 새로 추가하지 않습니다.

기존 업무에서 AI에게 위임할 수 있는 일을 찾을 수 없다면
임의로 만들지 말고 사용자에게 확인합니다.


## Task 후보 확인

정리한 결과를 바로 저장하지 않습니다.

반드시 채팅 응답 본문에
실제 내용이 채워진 **Markdown 표 1개**를 직접 출력합니다.

각 Task를 문단이나 목록으로 나열하지 않습니다.

다음과 같은 형식은 사용하지 않습니다.

단계: 1
Task: ...
실행 주체: ...
이유: ...

또한 `──────`와 같은 구분선을 사용하지 않습니다.

반드시 아래와 같이 `|`로 열이 구분된 Markdown 표 문법을 사용합니다.

| 단계 | Task | 실행 주체 | 이유 |
|---|---|---|---|
| 1 | 입력 자료 취합 및 병합 | 코드 | 정해진 규칙으로 반복 처리할 수 있음 |
| 2 | 발주별 상태 판정 및 협력사별 집계 | 코드 | 판단 기준과 계산식이 명확함 |
| 3 | 지연 사유 요약 | AI | 자유 서술 내용을 읽고 해석·요약해야 함 |
| 4 | 대시보드 작성 | 코드 | 정해진 구성에 결과를 배치하는 작업임 |
| 5 | 대시보드 최종 확인 | 사람 | 최종 확인과 판단이 필요함 |

위 표는 형식 예시입니다.
실제 응답에서는 사용자의 업무에 맞는 Task로 작성합니다.

### 출력 규칙

- 반드시 하나의 Markdown 표로 출력합니다.
- 열은 `단계 | Task | 실행 주체 | 이유` 4개만 사용합니다.
- 하나의 Task는 반드시 표의 한 행에 작성합니다.
- Task 설명이 길어도 별도의 문단으로 분리하지 않습니다.
- 표 앞에 Task별 설명을 따로 작성하지 않습니다.
- 표를 문장이나 목록으로 대체하지 않습니다.
- 최종 표에는 AI가 실행하는 Task가 최소 1개 포함되어야 합니다.

표를 출력한 뒤에는 아래 질문만 작성합니다.

> 실제 업무와 다른 부분이나, Task 또는 실행 주체를 수정하고 싶은 부분이 있나요?

여기서 반드시 응답을 종료하고 사용자의 답변을 기다립니다.
