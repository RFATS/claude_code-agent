# Parallel 패턴 가이드

## Parallel이란?

서로의 결과를 기다릴 필요가 없는 여러 AI Task를 동시에 수행하는 패턴입니다.

업무설계서에서 실행 주체가 `AI`인 Task만 대상으로 판단합니다.
코드 또는 사람이 수행하는 Task는 Parallel 추천 대상에서 제외합니다.


## Parallel을 적용하기 좋은 경우

Parallel은 **입력이 같은지 다른지**, 그리고
**같은 에이전트가 처리하는지 다른 에이전트가 처리하는지**를 기준으로
다음 4가지 유형으로 나누어 검토합니다.


### ① 같은 입력 × 같은 에이전트

같은 입력을 같은 역할의 여러 에이전트가
각각 독립적으로 처리하는 경우입니다.

같은 기준으로 여러 번 판단하거나
여러 결과를 만들어 비교하고 싶을 때 사용할 수 있습니다.

예시
- 같은 제안서를 여러 Reviewer가 같은 기준으로 각각 평가
- 같은 문제에 대해 여러 해결안을 각각 생성


### ② 같은 입력 × 다른 에이전트

같은 입력을 서로 다른 역할이나 전문성을 가진 에이전트가
각자의 관점에서 독립적으로 처리하는 경우입니다.

예시
- 같은 VOC를 품질 / 가격 / 서비스 관점에서 각각 분석
- 같은 문서를 기술 / 보안 / 법무 관점에서 각각 검토


### ③ 다른 입력 × 같은 에이전트

서로 다른 입력을 같은 역할의 에이전트가
동일한 기준과 방식으로 각각 독립 처리하는 경우입니다.

예시
- 협력사 A / B / C를 같은 기준으로 각각 평가
- 여러 계약서를 같은 기준으로 각각 요약
- 공장별 실적 데이터를 같은 방식으로 각각 분석


### ④ 다른 입력 × 다른 에이전트

서로 다른 입력을 각각 다른 역할이나 전문성을 가진 에이전트가
독립적으로 처리하는 경우입니다.

예시
- 시장 데이터는 시장분석 Agent, 기술 자료는 기술분석 Agent가 각각 분석
- 고객 데이터는 고객분석 Agent, 경쟁사 자료는 경쟁사분석 Agent가 각각 분석
- 공급사 자료는 공급망 Agent, 수요 자료는 수요분석 Agent가 각각 분석


## Parallel로 만들지 않는 경우

다음 중 하나에 해당하면 Parallel로 추천하지 않습니다.

- 실행 주체가 코드 또는 사람인 Task
- 앞 Task의 결과가 있어야 시작할 수 있는 Task
- 하나의 AI가 순서대로 처리하는 것이 자연스러운 Task
- 병렬화해도 실질적인 이점이 없는 Task

예시

[AI: 데이터 분석] → [AI: 보고서 작성]

보고서 작성은 데이터 분석 결과가 필요하므로
두 Task를 Parallel로 실행하지 않습니다.


## 업무설계서를 보고 판단하는 순서

1. 업무설계서에서 실행 주체가 `AI`인 Task만 찾습니다.
2. 각 AI Task를 서로 독립적인 작업으로 나누어 실행할 수 있는지 확인합니다.
3. 병렬로 실행할 작업의 입력이 같은지 다른지 확인합니다.
4. 같은 역할의 에이전트가 처리할지, 다른 역할의 에이전트가 처리할지 확인합니다.
5. ①~④ 유형 중 어디에 해당하는지 판단하고 Parallel 구조를 추천합니다.
6. 병렬로 나눈 작업들이 서로의 결과를 기다리지 않고 독립적으로 실행 가능한지 확인합니다.

Parallel이 적합하지 않다면 억지로 적용하지 않습니다.


## 결과 표현 방법

Parallel을 추천할 경우 다음 내용만 간단히 보여줍니다.

- 대상 AI Task
- Parallel 유형: ①~④
- 병렬로 실행할 작업
- Parallel을 적용하는 이유

추천한 구조가 전체 업무에서 어디에 위치하는지 알 수 있도록
코드 / AI / 사람 Task를 포함한 전체 Workflow를
상자와 화살표로 시각화합니다.

기존 업무설계서의 Workflow는 임의로 변경하지 않고,
추천한 Parallel 구조만 반영하여 보여줍니다.

예시

[코드: 데이터 전처리]
          ↓
      [AI: VOC 분석]
          ↓
   ┌──────┼──────┐
   ↓      ↓      ↓
[AI: 품질] [AI: 가격] [AI: 서비스]
   └──────┼──────┘
          ↓
   [AI: 결과 종합]
          ↓
    [사람: 최종 확인]


## 사용자 확인

추천한 Parallel 구조를 바로 확정하지 않습니다.

추천 결과와 전체 Workflow를 보여준 뒤
사용자에게 다음과 같이 확인합니다.

"이 Parallel 구조를 Workflow에 반영할까요?"

사용자가 수정을 요청하면
요청한 내용을 반영하여 구조를 다시 보여주고 확인받습니다.

사용자가 여러 Parallel 후보 중 일부만 선택할 수도 있습니다.
선택한 구조만 최종 Workflow에 반영합니다.


## Workflow 확정 및 저장

사용자가 Parallel 구조를 확정하면
확정된 내용만 전체 Workflow에 반영합니다.

코드 / AI / 사람 Task를 모두 포함하여
전체 Workflow를 다시 정리합니다.

확정된 전체 Workflow를 현재 폴더의
`workflow.md` 파일로 저장합니다.

`workflow.md`에는 최소한 다음 내용을 포함합니다.

- 전체 Task의 실행 순서
- 각 Task의 실행 주체: 코드 / AI / 사람
- 확정된 Parallel 구조와 유형
- Task 간 연결 관계
- 전체 Workflow 시각화

사용자가 확정하기 전에는 `workflow.md`를 생성하거나 수정하지 않습니다.
