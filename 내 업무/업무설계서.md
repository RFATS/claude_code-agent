# 업무 설계서

## 1. 자동화할 업무
- 업무명: 운영 Airflow DAG run fail 알림 대응 (약식 실습 버전)
- 업무 범위: 알림 메시지·실행 로그·DAG 소스코드 파일을 입력으로 받아 진성/가성 판별 → 원인 분석 및 수정 코드 작성 → PR 설명서 및 검증 리포트 작성까지 수행하고, 운영 배포(merge) 승인은 사람이 결정
- 실습용 약식 조정
  - 실제 Airflow 환경, 메신저 연동, Git/PR, 운영 배포는 사용하지 않음
  - 알림 메시지, Task 로그, DAG 소스코드, 샘플 데이터는 모두 가상의 파일로 대체
  - 개발단 DAG run 검증은 수정된 코드를 샘플 데이터로 로컬에서 실행하는 검증으로 대체
  - PR과 merge는 PR 설명서 문서 작성과 사람의 승인 체크로 대체

## 2. 입력 자료

| 자료 이름 | 형식 | 주요 내용 |
|---|---|---|
| Airflow DAG run fail 알림 메시지 | txt | 메신저로 온 알림 원문(DAG ID, Task ID, 실행 일시, fail 시각, 재시도 횟수, 로그 링크) |
| Airflow Task 실행 로그 | txt | fail된 Task의 실행 로그(에러 메시지, 스택트레이스, 재시도 이력, 재시도 성공 여부) |
| DAG 소스코드 | py | fail이 발생한 DAG와 Task 코드(데이터 적재·변환 로직). 수정 대상 소스 |
| fail 기간 처리 대상 샘플 데이터 | csv | fail 기간 동안 처리했어야 할 입력 데이터. 수정 코드 검증에 사용 |
| 과거 fail 대응 이력 (100건) | csv | 과거 fail 사례별 에러 유형, 판별 결과, 원인, 수정 요약, 사람의 승인/불승인 결정과 검토 의견. 판별·분석·수정 시 참고 |

## 3. 결과물

- 결과물 형태: fail 대응 리포트 (알림 1건당 리포트 1개)
- 구성:
  - 알림 정보 및 진성/가성 판별: DAG·Task·발생 시각, 판별 결과(진성/가성), 판별 근거(에러 유형·재시도 이력)
  - 진성 fail 원인 분석: 에러 발생 위치, 근본 원인, 영향 범위(fail 기간·대상 LOT·테스터)
  - 수정 코드 변경 내역: 변경 전/후 코드 diff, 수정 방침
  - 검증 결과 및 배포 승인 요청: fail 기간 샘플 데이터로 수정 코드를 실행한 결과, PR 설명 요약, 사람의 merge 승인 체크 항목
  - 가성으로 판별된 알림은 판별 섹션까지만 채우고 나머지 섹션은 "해당 없음"으로 표시

## 4. 세부 업무 단계

| 단계 | Task | 실행 주체 | 추가 기능 |
|---|---|---|---|
| 1 | 알림 메시지 분리 및 Task 로그 매칭·파싱 | 코드 | 없음 |
| 2 | 유사 과거 사례 검색 (알림의 DAG·Task·에러 내용으로 과거 이력 검색, 승인/불승인 구분) | 코드 | RAG: 과거 fail 대응 이력 100건(`data/past_cases.csv`)을 사례 1건당 Chunk 1개로 임베딩해 `rag/rag.db`에 저장하고 코사인 유사도로 검색 (`rag/build-rag.js`, `rag/search-rag.js`, Ch4 RAG 모듈 차용) |
| 3 | 진성/가성 판별 및 판별 근거 작성 (승인된 유사 사례는 적극 참고, 불승인 사례는 신중 판단) | AI | 없음 |
| 4 | 진성 fail 원인 분석 및 영향 범위 파악 (승인된 유사 사례는 적극 참고, 불승인 사례는 반면교사로 삼아 신중 추론) | AI | 없음 |
| 5 | 수정 코드 작성 (승인된 수정 방식은 참고하고, 불승인된 방식과 그 사유는 피함) | AI | 없음 |
| 6 | 수정 코드 검증 실행 (fail 기간 샘플 데이터로 로컬 실행, 수정 전/후 결과 비교) | 코드 | 없음 |
| 7 | 알림별 fail 대응 리포트 작성 (판별, 원인 분석, 코드 diff, 검증 결과, PR 설명 요약, 참고한 과거 사례, 승인 체크 항목) | AI | Skill: `reference/example.html`의 구성·완성도에 맞춰 리포트를 작성하는 규칙. 진성은 4개 섹션을 모두 채우고, 가성은 판별 섹션까지만 채운 뒤 나머지는 "해당 없음"으로 표시 |
| 8 | 리포트 검토 및 승인/불승인 결정 (결정 결과와 사유를 과거 사례 이력에 기록) | 사람 | 없음 |
